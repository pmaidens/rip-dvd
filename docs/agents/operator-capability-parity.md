# Operator capability parity

The web interface and `rip-dvd` CLI are separate adapters over the same
application operations. A web operator feature is not complete until this
inventory names its CLI equivalent and its externally observable behavior
coverage. SQL access, a worker-only API, or a test of an internal helper does
not count as a CLI equivalent.

For every operator change:

1. Update the matching inventory row. Add a row when the capability is new.
2. Implement the CLI behavior without calling the web service.
3. Test the workflow through the public command runner with real persistence.
4. Add focused HTTP parity coverage when the web and CLI adapters mutate or
   validate the same operation.
5. Add browser coverage only for behavior that depends on browser interaction.
6. Run `pnpm check`, `pnpm test:browser`, and the installed-executable smoke.

The repository test suite checks that every operator API route and every
top-level CLI command remains represented here. That catches additions, but it
does not prove a row is honest. Reviewers must follow the cited behavior test
and compare both adapters with the same application rule.

Browser permission and Home Screen installation are browser-only. The CLI administers subscriptions directly through shared application operations. Notification dispatch runs independently in the managed notification worker.

Archive Job publication, ordinary and classified failure, and expired-claim failure
atomically queue notifications at persistence. These producers add no operator
mutation command. Existing notification delivery inspection and Archive Job detail
commands expose the same outcomes to HTTP and JSON CLI clients. Cancellation and
cooperative abort do not emit failure notifications.

Archive Recovery completion and committed attention outcomes also queue events
within their persistence transactions. Pass settlement, reconciled completion,
storage-fault pauses, failed continuation verification or checkpoint
reconciliation, and unreconcilable Stop faults reuse the shared producer contract. They add no operator command or
background work type. The recovery worker workflow tests inspect the same
durable results through public JSON CLI and HTTP operations and dispatch through
the controlled sender. Initial completed Recovery, productive or no-progress
passes, tolerable reads, and interruption alone do not create Recovery alerts.

Notification worker update checks, activation and subscription continuity are
browser-only lifecycle behavior, covered by `notification-updates.e2e.ts` on the
separate secure origin. They add no server mutation or CLI command. Existing
`rip-dvd notifications` subscription, test and delivery operations remain the
shared administration contract through upgrades. CLI workflows use real SQLite
persistence in `apps/operator-cli/src/notifications.test.ts`; focused HTTP parity
remains in `apps/web/app/api/notifications/route.test.ts`.

prerequisites. Corrected extents retain strict completeness and title-map proof.

continue to reject new evidence-format admission; checkpoint publication and
policy-version binding are separate work. Worker behavior is covered by
`apps/archive-worker/src/dvd-initial-boundary.test.ts` and
`apps/archive-worker/src/dvd-full-extent-validator.test.ts`.
